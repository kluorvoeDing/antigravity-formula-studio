# 模組資料撰寫規範

每個模組要同時做到兩件事：**教會讀者一個名詞**，以及**提供一段任何 AI 都看得懂的指示句**。
型別與常數定義在 `data/schema.js`；示範請看 `data/web/03-section.js`。

## 檔案

- 一個類別一個檔，`export default { id, zh, en, intro, groups, modules }`。
- 純資料：不含函式、不 import、任何字串都不得含 HTML 標籤。
- 不得自行增刪或改名既有的 `id`、`groups`。
- 格式：2 空格縮排、雙引號、尾逗號。中文一律用全形標點（，。：；（）「」）。
- 寫完執行 `node scripts/validate.mjs <檔案路徑>`，必須零錯誤。

## 欄位

| 欄位 | 規則 |
|---|---|
| `id` | `<主題>.<類別>.<slug>`，小寫 kebab。 |
| `zh` | 2–14 字。業界通行的中文說法；沒有通行說法就直譯，不要自創花俏名稱。 |
| `en` | 業界通用術語，Title Case。這是讀者之後會拿去搜尋的詞，務必正確。 |
| `aka` | 選填。其他常見說法（中英皆可），供搜尋用。 |
| `what` | 一句話，12–70 字。描述**畫面上會看到什麼**，讓沒聽過這個詞的人能想像。 |
| `when` | 1–3 條，每條 6–44 字。具體情境：內容量、受眾、裝置、素材條件。 |
| `avoid` | 1–3 條，每條 6–44 字。具體情境，**不得只是 `when` 的反面**。 |
| `prompt` | 30–200 字，1–3 句。見下節。 |
| `accept` | 選填，10–90 字。一句可以實際檢查的條件（寬度、數量、行為）。 |
| `group` | 類別有多個分組時必填。 |
| `tags` | 1–5 個，只能用 `data/schema.js` 的 `TAGS`。 |
| `related` | 選填。讀者接著可能想看的模組 id。 |
| `conflicts` | 選填。跨分組的互斥（同一個單選組內不用寫）。 |
| `requires` | 選填。`[{ anyOf: [id...], why: "原因" }]`。 |
| `needs` | 選填。執行這個選項的 AI 需要的能力：`files`、`shell`、`network`。 |
| `note` | 選填。只顯示在介面、不進提示詞的提醒。 |
| `preview` | 看得見的模組必填。見「預覽」一節。 |

## `prompt` 怎麼寫

引擎會自動在前面加上「`zh`（`en`）：」，所以 `prompt` 本身不必重複名稱。

- **祈使句、自足**：單獨拿出來讀也完整，不引用其他模組，不寫「如前所述」。
- **描述結果，不描述工具**：寫「卡片依序由下往上淡入，每張間隔 60 毫秒」，不寫「使用某某函式庫」。技術類別除外。
- **盡量可量化**：欄數、數量、字數上限、比例、時間、斷點寬度。
- **包含響應式行為**：版面類的模組要交代窄螢幕時怎麼變。
- **不得出現**任何 AI 產品或工具的名稱，也不得出現「上述、前述、剛才、附件、這個對話」等指涉字眼。完整清單見 `BANNED`。

好的例子：

> 首屏採左右兩欄：左欄放主標題（不超過 14 個字）、兩行以內的說明、一個主要按鈕與一個次要文字連結；右欄放產品畫面或情境圖，高度與左欄對齊。寬度小於 768px 時改為上下堆疊，文字在上。

不好的例子：

> 打造極致吸睛的次世代 Hero 區塊，展現品牌高級感。（沒有任何可執行的資訊）

## `what`、`when`、`avoid` 怎麼寫

- `what` 禁用空泛形容詞（極致、高級感、次世代、靈動、頂級、完美、震撼、驚豔）。
- `when` 與 `avoid` 要寫到讀者能拿來做判斷：「功能之間有明顯主次，需要突顯其中一個」比「不適合時」有用。
- 同一個檔案裡，不同模組的 `when` / `avoid` 不要套同一個句型。每個模組都應該有只屬於它的判斷依據。

## 預覽

預覽是宣告式規格，由固定的渲染器畫成中性灰線框。資料檔不寫 HTML 或 CSS。

`wire`（版面線框）：

```js
preview: {
  kind: "wire",
  frame: "desktop", // 或 "mobile"
  rows: [
    ["nav"],
    [{ t: "stack", hl: true, items: ["h1", "p", "btns"] }, { t: "img", hl: true }],
    ["logos"],
  ],
}
```

- `rows` 是由上到下的 1–7 列，每列 1–4 個基元，同一列等寬並排；`span: 2` 可讓某格佔兩份寬度。
- 基元清單見 `WIRE_PRIMS`。`stack` 是垂直堆疊的容器，用 `items` 放內容。
- **至少一個基元要有 `hl: true`**，標出「這個模組本身」；其餘是前後文。
- 前後文只放一兩列，讓讀者看得出這個區塊在頁面上的位置即可。

其他預覽類型（`specimen`、`type`、`palette`、`shape`、`motion`、`tree`、`copy`、`versus`）的規格，見各類別檔案開頭已有的示範模組。

## 交付前自我檢查

1. `node scripts/validate.mjs <檔案路徑>` 零錯誤。
2. 每個 `en` 都是真實存在、搜尋得到的術語。
3. 隨機挑三個模組，只讀 `what` 能不能想像出畫面；只讀 `prompt` 能不能直接動手做。
4. 沒有兩個模組的 `when` / `avoid` 幾乎一樣。
