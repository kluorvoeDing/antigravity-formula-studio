# 任務
請製作一個完整的網站。
本文件是完整規格。請一次完成全部內容，不要只給大綱、片段或示意。
規格沒寫到的地方，不要停下來發問；請自行做出合理的決定，並在交付時以「我的假設」為標題逐條列出。
各項要求若互相牴觸，排在前面的優先：個人風格、禁止事項、網站類型、視覺風格、色彩與字體與形狀、整體版型、個別區塊與元件。取捨的結果請一併列入「我的假設」。

## 定位與受眾
- 網站類型：上線前等候頁（Waitlist Page）——這是一個產品上線前的等候登記頁，唯一目的是收集想搶先使用的人的 Email。頁面只講一件事：產品要解決的問題（一句標題加兩行以內說明）、一個 Email 欄位與送出按鈕；送出後原地顯示登記成功與預計上線時間，除隱私說明外不放其他離站連結。

## 頁面結構
### 整體版型
- 單欄置中（Single-Column Layout）：採單欄置中版型：各區塊由上到下依序堆疊、水平置中，不使用側欄，區塊之間保留一致的垂直間距。只有連續的長文段落限制行寬在 720px 以內；卡片列、圖片與表格等區塊不受此限，可以比段落寬並在區塊內並排分欄。寬度小於 768px 時一律回到單欄。
### 區塊（由上到下，依此順序）
1. 內嵌表單主視覺（Hero with Signup Form）：首屏左欄放主標題、兩行以內的說明，下方一列並排電子郵件輸入框與送出按鈕，按鈕寫出具體結果（例如「取得試用帳號」），表單下一行小字說明不會濫發郵件；右欄放產品圖。送出後在原位顯示成功訊息，不跳頁。寬度小於 640px 時改為單欄，輸入框與按鈕上下堆疊並撐滿寬度。
2. 常見問題摺疊清單（FAQ Accordion）：列出 6 到 8 個常見問題，以摺疊清單呈現：每列顯示問題與一個展開指示圖示，點擊後在下方展開答案、圖示隨狀態改變，再點一次收合。預設展開第一題。每個問題用按鈕實作，可用 Tab 移動、Enter 或空白鍵切換，並設定 aria-expanded 與 aria-controls。
3. 極簡頁尾（Minimal Footer）：頁尾只用一列：左側放標誌或品牌名稱與版權年份，右側放 2 到 4 個文字連結（例如隱私權政策、聯絡我們）與最多 4 個社群圖示，與上方內容明確隔開，上下留白保持緊湊。社群圖示要有無障礙名稱。寬度小於 640px 時改為置中的兩行，連結在上、版權在下。

## 視覺系統
### 字體排印
- 等寬字點綴（Monospace Accents）：中文標題與內文使用黑體（例如 Noto Sans TC）；英文與數字的標籤、日期、價格、版本號與程式碼使用等寬字（例如 JetBrains Mono 或 IBM Plex Mono），字重 400 到 500，字級比內文小一級並略放寬字距。等寬字只用於點綴，約佔全頁文字量一成以內。
### 色彩
- 純黑白（Black & White）：色彩只用黑與白，最多加一階中灰作為分隔線與次要文字；介面不使用任何彩色，錯誤與成功狀態改用圖示加文字說明。層次靠字級、粗細、反白色塊與留白建立，可點擊的文字以底線或反白標示。文字對比達 4.5:1。
- 只做深色模式（Dark Mode Only）：只提供深色模式：明確宣告色彩配置為深色（color-scheme: dark），背景用接近黑的深灰，卡片、選單等較高的表面依序調亮一階，共 3 到 4 階。內文用略帶灰的白而非純白，強調色調亮或降低飽和以免刺眼。不跟隨系統的淺色設定。文字對比達 4.5:1。
### 間距與形狀
- 直角（Sharp Corners）：全站所有元件的圓角一律為 0：按鈕、卡片、輸入框、圖片、標籤、彈出視窗都是直角。唯一的例外是頭像與狀態圓點可以是正圓。
- 粗框線（Thick Borders）：容器與互動元件用 2px（大型卡片可用 3px）的深色實線框住，顏色接近內文色。需要表示浮起時，加一塊不模糊的實心陰影，向右下各偏移 4px；按下時陰影歸零、元件同步位移 4px。不要使用帶模糊的柔和陰影。
### 圖像與媒體
- 顆粒質感（Film Grain Texture）：在主視覺或大色塊背景上疊一層細顆粒雜訊：以內嵌 SVG 的 feTurbulence 濾鏡產生，不透明度 4% 到 8%，設定 pointer-events: none 不擋點擊。不載入外部雜訊圖檔，也不讓顆粒蓋住內文段落。覆蓋層純屬裝飾，對輔助科技隱藏。

## 動態與互動
- 克制的動態（Subtle Motion）：動態以回應操作為主：點擊與懸停的過渡預設 150 到 250 毫秒、位移不超過 8px、緩動用減速曲線（ease-out），展開、收合、切換、出現與消失才加動畫，預設不加自動播放的裝飾動態。已選效果另有時長、曲線或減少動態規定時，以該效果為準；訪客設定減少動態（prefers-reduced-motion）時改為立即切換。
- 載入交錯進場（Staggered Page Load）：只在首屏套用載入進場：導覽列、主標題、說明、按鈕、主圖依序淡入並上移 12px，每項 400 毫秒、間隔 80 毫秒、使用減速曲線，整段在 900 毫秒內結束。首屏以下不套用，進場期間按鈕仍可點擊。訪客設定減少動態時直接顯示。

## 技術與交付
- 單一 HTML 檔（Single HTML File）：成品是單一 HTML 檔：所有 CSS 寫在 head 的 style 標籤內，所有 JavaScript 寫在 body 結尾的 script 標籤內，不使用任何建置工具或框架。除字體外不得依賴外部檔案；字體可從公開的字體服務載入，但必須指定系統字體作為後備。檔案在沒有伺服器的情況下直接開啟即可完整運作。
- 原生 CSS 與自訂屬性（Plain CSS with Custom Properties）：樣式只使用原生 CSS：在根層級以自訂屬性定義設計變數（顏色、字級、間距、圓角、陰影），其餘樣式一律引用變數而不寫死數值。使用現代版面語法（Grid、Flexbox、clamp()、邏輯屬性），類別名稱以元件為單位命名。不使用任何 CSS 框架或前置處理器。
- 表單即時驗證（Inline Form Validation）：表單在欄位失去焦點時驗證：錯誤訊息顯示在該欄位正下方，說明哪裡不對與如何修正，並以屬性與欄位關聯（aria-describedby、aria-invalid）。使用者開始修正後錯誤即時消失。送出時若有錯誤，焦點移到第一個錯誤欄位。送出成功後顯示明確的確認狀態。
- 交付方式：若你能在工作目錄建立檔案，請直接建立，完成後列出檔案清單與開啟方式；若不能，請逐一以程式碼區塊輸出每個檔案的完整內容，並在每個區塊的前一行標明檔案路徑。不得省略任何部分，也不得以「其餘相同」帶過。
### 品質要求
- 行動優先響應式（Mobile-First Responsive）：以行動優先的方式撰寫樣式：基礎樣式針對 375px 寬的螢幕，再以最小寬度的媒體查詢在 768px 與 1200px 逐步加寬版面。所有寬度下頁面整體都不得出現水平捲軸（容器內刻意的橫向捲動除外）；觸控裝置上的可點擊目標至少 44px 見方；圖片與影片不超出容器。
- 基本無障礙（Accessibility Basics (WCAG AA)）：達到 WCAG 2.2 AA 的基本要求：內文與背景對比至少 4.5:1，大字與介面元件至少 3:1；所有功能可只用鍵盤操作，聚焦時有清楚可見的外框；有意義的圖片有替代文字，裝飾圖片的替代文字留空；表單欄位都有關聯的標籤；不只靠顏色傳達資訊。
- 搜尋與分享標籤（SEO & Social Meta Tags）：在 head 中加入完整的中繼資料：不超過 30 個中文字的 title、不超過 80 個中文字的 description、標準網址（canonical），以及 Open Graph 的標題、說明、圖片（1200×630）與類型，html 標籤設定 lang 屬性。每個頁面的 title 與 description 都不相同。

## 內容與文案
- 介面與文案語言：繁體中文（台灣用語）
- 語氣：大膽自信（Bold & Confident）——文案大膽自信：主標題不超過 12 字，用肯定句直接下結論，不加「或許」「可能」「幫助您」這類緩衝詞；說明用 2–3 個短句，以句號斷開。以「你」稱呼讀者、以「我們」做出承諾；每個主張後接一個可驗證的事實，不杜撰數據，不使用「第一」「唯一」「最強」，全頁驚嘆號最多一個。
- 依本規格的定位寫出具體、可直接上線的文案；不得使用 Lorem ipsum 或「標題文字」這類佔位字。素材沒提供的產品細節（功能、價格、日期）可自行合理設定並在「我的假設」中註明；客戶名稱、見證與成果數字若沒有提供，一律明確標示為「示意」。

## 禁止事項
- 禁用藍紫漸層（No Purple-Blue Gradients）：不得使用藍色到紫色的漸層，也不得使用漸層文字、背景光暈球與霓虹發光效果。背景使用純色；需要層次時改用明度不同的同色系色塊或留白。
- 禁用表情符號當圖示（No Emoji as Icons）：不得以表情符號作為圖示、項目符號或標題裝飾。需要圖示的地方使用風格一致的內嵌 SVG；沒有合適圖示時寧可不放。
- 禁用空泛標語（No Filler Copy）：文案不得使用放在任何產品都成立的空泛句子，例如「釋放潛能」「重新定義」「無縫整合」「賦能團隊」「次世代」。每個標題都要包含這個產品特有的對象、動作或數字；把產品名稱換成別的產品後句子仍然成立，就必須重寫。
- 禁止罐頭首屏（No Generic Hero）：首屏不得套用「置中標題、一行副標、兩顆按鈕、背景光暈」的固定公式。首屏要放這個產品真實的畫面、實物或具體數字（沒有素材時放標示用途的佔位塊，不要編造），標題直接說明產品做什麼，只保留一個主要按鈕。
