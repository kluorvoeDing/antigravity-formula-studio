# 任務
請製作一個完整的網站。
本文件是完整規格。請一次完成全部內容，不要只給大綱、片段或示意。
規格沒寫到的地方，不要停下來發問；請自行做出合理的決定，並在交付時以「我的假設」為標題逐條列出。
各項要求若互相牴觸，排在前面的優先：個人風格、禁止事項、網站類型、視覺風格、色彩與字體與形狀、整體版型、個別區塊與元件。取捨的結果請一併列入「我的假設」。

## 定位與受眾
- 網站類型：資料儀表板（Dashboard）——這是一個給回訪使用者看的資料儀表板，目的是讓人在 5 秒內判斷關鍵指標是好是壞，並能往下查明細。最重要的 3 到 5 個數字放最前面並附上與前期的比較，其次是趨勢圖，最後是可排序的明細表；不放行銷文案與號召註冊的按鈕。

## 頁面結構
### 整體版型
- 側欄應用框架（Sidebar App Shell）：採應用程式框架：左側是寬 240px 的固定側欄，放標誌、5 到 8 個含圖示的導覽項目並標示目前所在項目；右側主內容區獨立捲動，頂端有一條放頁面標題與主要操作的橫列。寬度小於 1024px 時側欄收合為抽屜，以選單按鈕開啟。
### 區塊（由上到下，依此順序）
1. 數字成果列（Stats Band）：一列並排 3 到 4 組數據，每組是一個大數字（含單位，例如「12 萬+」「38%」）與一行不超過 12 字的說明，各組之間用細分隔線或等距留白隔開。區塊底部用一行小字註明數據來源與統計時間。寬度小於 768px 時改為 2 欄網格。
2. 時間軸（Timeline）：以一條垂直主線串起 4 到 8 個節點，每個節點標示日期或年份、不超過 14 字的事件標題與一兩句說明，可附一張小圖，依時間由早到晚由上往下排。桌面寬度時節點左右交替排在主線兩側；寬度小於 768px 時主線移到左側，所有節點排在右側。
3. 極簡頁尾（Minimal Footer）：頁尾只用一列：左側放標誌或品牌名稱與版權年份，右側放 2 到 4 個文字連結（例如隱私權政策、聯絡我們）與最多 4 個社群圖示，與上方內容明確隔開，上下留白保持緊湊。社群圖示要有無障礙名稱。寬度小於 640px 時改為置中的兩行，連結在上、版權在下。
### 元件與互動模式
- 分頁標籤（Tabs）：以分頁標籤切換同層級的內容：上方是 2 到 5 個標籤，目前選中的標籤有明顯的底線或底色，下方面板只顯示對應內容。左右方向鍵在標籤間移動，Home 與 End 跳到頭尾，Tab 鍵從標籤直接進入面板（role="tablist"、"tab"、"tabpanel"，選中者 aria-selected="true"，以 aria-controls 對應面板）。
- 快顯通知（Toast Notification）：操作成功的回饋以快顯通知呈現：一則不超過 20 個字的訊息從畫面右下角滑入，停留 4 秒後自動淡出，滑鼠停在上面時暫停計時。同時出現多則時向上堆疊。訊息必須放在即時播報區域（aria-live="polite"）讓螢幕閱讀器讀出。
- 下拉選單（Dropdown Menu）：按鈕下方展開 3 到 8 個項目的選單，靠左對齊按鈕。點項目後執行並收起，點選單外或按 Esc 也收起；上下方向鍵移動、Enter 選取、Home 與 End 跳到頭尾。刪除這類危險動作排在最後，以分隔線隔開（aria-haspopup="menu"、aria-expanded、role="menu"、role="menuitem"）。
- 指令面板（Command Palette）：按 Cmd 或 Ctrl 加 K 開啟置中的指令面板：上方是搜尋框並自動聚焦，下方依「頁面」與「操作」分組列出最多 8 筆結果，輸入時即時過濾。上下鍵移動、Enter 執行、Esc 關閉並把焦點還給原處（面板 role="dialog"，搜尋框 role="combobox"，結果 role="listbox"，aria-activedescendant 指向目前項目）。
- 骨架屏（Skeleton Loader）：資料載入期間，用占位形狀取代內容：形狀、數量與尺寸要和真實內容相符（頭像為圓形、標題為一條長條、內文為 3 條不等長的長條），載入完成後原位替換，版面不可位移。載入區塊標示 aria-busy="true"，若使用者設定減少動態（prefers-reduced-motion）則不做閃動。
- 資料表格（Data Table）：資料表格含固定表頭，文字欄靠左、數字欄靠右，每列高度一致。點擊表頭依該欄升序或降序排序並顯示方向箭頭；上方放搜尋框，底部每頁 20 筆分頁。寬度小於 768px 時第一欄固定、其餘橫向捲動。可排序的表頭內放按鈕，排序中的欄位標 aria-sort。
- 空狀態（Empty State）：列表為空時在內容區中央放空狀態：一個簡單圖示或插圖、不超過 16 個字的標題說明現況、一行說明原因或好處，以及一個引導下一步的主要按鈕，例如「新增第一個專案」。搜尋無結果時改成「沒有符合關鍵字的結果」，並提供清除篩選的連結。

## 視覺系統
### 字體排印
- 怪誕黑體（Grotesque Sans）：中文使用字面方正、筆畫末端平直的黑體（例如 Noto Sans TC），英文使用 grotesque 或 neo-grotesque 類無襯線字（例如 Archivo 或 Hanken Grotesk）。標題字重 700、內文 400，英文標題字距收緊 -0.01em 到 -0.03em、中文標題不超過 -0.01em；不搭配襯線字或手寫字。
- 模組化字級（Modular Type Scale）：以 16px 為內文基準，用固定比例 1.25 往上推出 6 級字級：16、20、25、31、39、49px，標題、內文與說明文字只能從這組數值挑選。寬度小於 768px 時改用比例 1.2（16、19、23、28、33px），只用前五級。
### 色彩
- 黑白灰加一個強調色（Monochrome + One Accent）：色彩採中性色加單一強調色：背景、文字、邊框只用黑、白與 4 到 5 階灰；另選一個強調色，只用在主要按鈕、連結、選中狀態與重點數字，面積不超過畫面的 10%。不得出現第二種彩色，成功與錯誤狀態除外。
- 深淺色可切換（Light & Dark Mode Toggle）：同時提供淺色與深色模式：所有顏色以語意化的自訂屬性定義（例如背景、表面、主要文字、次要文字、邊框、強調），兩種模式各給一組值。預設跟隨系統設定（prefers-color-scheme），並提供一個切換按鈕，選擇結果儲存在瀏覽器本機，下次造訪沿用。深色模式的背景用深灰而非純黑。
### 間距與形狀
- 分級圓角（Radius Scale）：圓角採三級階層並以自訂屬性定義：小型元件（按鈕、輸入框、標籤）6px，卡片 12px，大型容器與彈出視窗 20px。巢狀時內層圓角必須小於外層，差值等於兩者之間的內距。不得所有元件共用同一個圓角值。
- 細線分隔（Hairline Borders）：層次只靠邊框表達：卡片、輸入框與區塊分界使用 1px 實線，顏色為比背景略深的中性色；全站不使用任何陰影。浮層（下拉選單、彈出視窗）以稍深的邊框加上不同的底色與背景區分。
- 緊湊密集（Compact Density）：採緊湊的間距：所有間距取自 4px 的倍數階層（4、8、12、16、24）；表格列高 32px，按鈕高度 28px 到 32px，區塊間距不超過 24px。可點擊目標在觸控裝置上仍須至少 44px 高。
### 圖像與媒體
- 線條圖示（Line Icons）：圖示統一使用線條風格的內嵌 SVG：線寬 1.5px、端點與轉角為圓頭、畫在 24px 的格子上，顏色繼承文字顏色（currentColor）。整站只用同一套圖示，不混用填色圖示，也不得以表情符號代替圖示。純裝飾的圖示對輔助科技隱藏，單獨作為按鈕的圖示要有文字標籤。
- 資料圖表（Data Visualization）：以內嵌 SVG 繪製圖表，不載入圖表函式庫：每張圖只表達一個重點，有標題、座標軸標籤與單位，關鍵數值直接標在圖上，並設定 viewBox 隨容器縮放。沒有提供資料時，使用明確標示「示意數據」的假資料，不冒充真實成果。每張圖附一段文字摘要或資料表給輔助科技。

## 動態與互動
- 克制的動態（Subtle Motion）：動態以回應操作為主：點擊與懸停的過渡預設 150 到 250 毫秒、位移不超過 8px、緩動用減速曲線（ease-out），展開、收合、切換、出現與消失才加動畫，預設不加自動播放的裝飾動態。已選效果另有時長、曲線或減少動態規定時，以該效果為準；訪客設定減少動態（prefers-reduced-motion）時改為立即切換。

## 技術與交付
- React 專案（React + Vite Project）：成品是以 Vite 建立的 React 專案，使用 TypeScript：每個頁面區塊是一個獨立元件，放在 src/components。附上 package.json 與 README，說明安裝、啟動、建置三個指令與所需的 Node 版本。除 React 本身外，每多引入一個套件都要在 README 說明原因。
- 原生 CSS 與自訂屬性（Plain CSS with Custom Properties）：樣式只使用原生 CSS：在根層級以自訂屬性定義設計變數（顏色、字級、間距、圓角、陰影），其餘樣式一律引用變數而不寫死數值。使用現代版面語法（Grid、Flexbox、clamp()、邏輯屬性），類別名稱以元件為單位命名。不使用任何 CSS 框架或前置處理器。
- 本機儲存（Local Storage Persistence）：使用者的設定與輸入內容儲存在瀏覽器的 localStorage：每次變更後 300 毫秒內寫入，載入頁面時還原。讀寫都要包在錯誤處理中且只在瀏覽器端執行，儲存空間不可用時網站仍能正常運作。儲存的資料帶版本號，並提供一個「清除資料」的操作。
- 交付方式：若你能在工作目錄建立檔案，請直接建立，完成後列出檔案清單與開啟方式；若不能，請逐一以程式碼區塊輸出每個檔案的完整內容，並在每個區塊的前一行標明檔案路徑。不得省略任何部分，也不得以「其餘相同」帶過。
### 品質要求
- 行動優先響應式（Mobile-First Responsive）：以行動優先的方式撰寫樣式：基礎樣式針對 375px 寬的螢幕，再以最小寬度的媒體查詢在 768px 與 1200px 逐步加寬版面。所有寬度下頁面整體都不得出現水平捲軸（容器內刻意的橫向捲動除外）；觸控裝置上的可點擊目標至少 44px 見方；圖片與影片不超出容器。
- 基本無障礙（Accessibility Basics (WCAG AA)）：達到 WCAG 2.2 AA 的基本要求：內文與背景對比至少 4.5:1，大字與介面元件至少 3:1；所有功能可只用鍵盤操作，聚焦時有清楚可見的外框；有意義的圖片有替代文字，裝飾圖片的替代文字留空；表單欄位都有關聯的標籤；不只靠顏色傳達資訊。
- 完整鍵盤操作（Keyboard Navigation）：Tab 順序與畫面閱讀順序一致，不使用大於 0 的 tabindex；頁面第一個可聚焦元素是「跳到主要內容」連結；自訂元件支援對應按鍵：選單與分頁用方向鍵移動，Esc 關閉浮層，Enter 與空白鍵觸發按鈕。焦點不能卡在任何元件裡出不來。
- 焦點管理（Focus Management）：開啟對話框或抽屜時把焦點移到框內第一個可操作元素，Tab 只在框內循環，按 Esc 關閉後焦點回到開啟它的按鈕；單頁應用切換畫面後把焦點移到新畫面的主標題；表單送出失敗時把焦點移到第一個有錯誤的欄位。
- 載入、錯誤與空狀態（Loading, Error & Empty States）：每個讀取資料的區塊都做三種狀態：等待超過 1 秒時顯示與最終版面同尺寸的骨架或進度提示，超過 10 秒顯示進度或預估時間；失敗時用一句話說明原因並提供重試按鈕；零筆時說明為何是空的並給一個下一步操作。結果與錯誤訊息以 aria-live 區域告知螢幕閱讀器。
- 避免版面跳動（Layout Stability (CLS)）：累計版面位移（CLS）保持在 0.1 以下：所有圖片、影片與 iframe 寫明寬高或 aspect-ratio；廣告、嵌入內容與非同步載入的區塊預留最小高度；除非是回應使用者操作，否則不在既有內容上方插入橫幅或通知；備援字體調整到與網頁字體的字寬接近。

## 內容與文案
- 介面與文案語言：繁體中文（台灣用語）
- 語氣：技術精確（Technical & Precise）——文案技術精確：以產品或功能為主詞寫陳述句，每句不超過 30 字；每個功能都寫出規格、數值與單位，例如人數上限、延遲、支援的格式或協定，數字用阿拉伯數字，沒有確切數值就標「待確認」，不可杜撰。術語第一次出現時附一句白話解釋；不用「強大」「高效」「智慧」「無縫」這類無法驗證的形容詞，也不用驚嘆號。
- 依本規格的定位寫出具體、可直接上線的文案；不得使用 Lorem ipsum 或「標題文字」這類佔位字。素材沒提供的產品細節（功能、價格、日期）可自行合理設定並在「我的假設」中註明；客戶名稱、見證與成果數字若沒有提供，一律明確標示為「示意」。

## 禁止事項
- 禁用藍紫漸層（No Purple-Blue Gradients）：不得使用藍色到紫色的漸層，也不得使用漸層文字、背景光暈球與霓虹發光效果。背景使用純色；需要層次時改用明度不同的同色系色塊或留白。
- 禁用表情符號當圖示（No Emoji as Icons）：不得以表情符號作為圖示、項目符號或標題裝飾。需要圖示的地方使用風格一致的內嵌 SVG；沒有合適圖示時寧可不放。
- 禁用空泛標語（No Filler Copy）：文案不得使用放在任何產品都成立的空泛句子，例如「釋放潛能」「重新定義」「無縫整合」「賦能團隊」「次世代」。每個標題都要包含這個產品特有的對象、動作或數字；把產品名稱換成別的產品後句子仍然成立，就必須重寫。
