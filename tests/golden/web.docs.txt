# 任務
請製作一個完整的網站。
本文件是完整規格。請一次完成全部內容，不要只給大綱、片段或示意。
規格沒寫到的地方，不要停下來發問；請自行做出合理的決定，並在交付時以「我的假設」為標題逐條列出。
各項要求若互相牴觸，排在前面的優先：個人風格、禁止事項、網站類型、視覺風格、色彩與字體與形狀、整體版型、個別區塊與元件。取捨的結果請一併列入「我的假設」。

## 定位與受眾
- 網站類型：文件網站（Documentation Site）——這是一個技術文件網站，讀者帶著具體問題來查答案。每頁要有三個資訊區：可收合的章節目錄並標示目前頁面、文章本文、本頁標題索引；窄螢幕時目錄與索引收合成可展開的選單。程式碼範例可一鍵複製，每頁底部有上一頁與下一頁連結。

## 頁面結構
### 整體版型
- 側欄應用框架（Sidebar App Shell）：採應用程式框架：左側是寬 240px 的固定側欄，放標誌、5 到 8 個含圖示的導覽項目並標示目前所在項目；右側主內容區獨立捲動，頂端有一條放頁面標題與主要操作的橫列。寬度小於 1024px 時側欄收合為抽屜，以選單按鈕開啟。
### 區塊（由上到下，依此順序）
1. 固定頂部導覽列（Sticky Navbar）：頁面頂端放一條固定導覽列：左側是標誌，中間是 3 到 5 個錨點連結，右側是一個主要按鈕。捲動時導覽列固定在視窗頂端，離開頁首後改為不透明背景，與下方內容明確區隔，避免文字透出重疊。寬度小於 768px 時把連結收進可開合的選單。
2. 功能卡片網格（Feature Grid）：以區塊標題加一行說明開頭，下方排 3 或 6 張等寬卡片（桌面 3 欄、平板 2 欄、手機 1 欄）。每張卡片包含一個圖示、不超過 8 個字的功能名稱與兩行以內的說明；所有卡片高度一致，文字靠左對齊。
3. 常見問題摺疊清單（FAQ Accordion）：列出 6 到 8 個常見問題，以摺疊清單呈現：每列顯示問題與一個展開指示圖示，點擊後在下方展開答案、圖示隨狀態改變，再點一次收合。預設展開第一題。每個問題用按鈕實作，可用 Tab 移動、Enter 或空白鍵切換，並設定 aria-expanded 與 aria-controls。
4. 多欄頁尾（Multi-Column Footer）：頁尾分為 4 欄：第一欄放標誌與一句品牌描述，其餘 3 欄各有一個小標題與 4 到 5 個連結。最底部以分隔線或留白與上方隔開，左側放版權聲明，右側放隱私權政策與服務條款連結。寬度小於 768px 時改為 2 欄。
### 元件與互動模式
- 分頁標籤（Tabs）：以分頁標籤切換同層級的內容：上方是 2 到 5 個標籤，目前選中的標籤有明顯的底線或底色，下方面板只顯示對應內容。左右方向鍵在標籤間移動，Home 與 End 跳到頭尾，Tab 鍵從標籤直接進入面板（role="tablist"、"tab"、"tabpanel"，選中者 aria-selected="true"，以 aria-controls 對應面板）。
- 快顯通知（Toast Notification）：操作成功的回饋以快顯通知呈現：一則不超過 20 個字的訊息從畫面右下角滑入，停留 4 秒後自動淡出，滑鼠停在上面時暫停計時。同時出現多則時向上堆疊。訊息必須放在即時播報區域（aria-live="polite"）讓螢幕閱讀器讀出。

## 視覺系統
### 視覺風格
- 瑞士極簡（Swiss Minimalism）：採瑞士極簡風格：所有元素對齊 12 欄格線並靠左；只用一種無襯線字體，以字級與粗細的強烈對比建立層次；色彩限黑、白與一個純色重點色；不使用陰影、漸層、圓角與任何裝飾性圖形，分隔只靠留白與 1px 細線。
### 字體排印
- 襯線標題配黑體內文（Serif Display + Sans Body）：字體分兩個角色：標題使用襯線體（中文明體、英文 serif），字重 600 以上；內文與介面文字使用無襯線體（中文黑體、英文 sans-serif），字重 400。全站只用這兩個字族，不再引入第三種；主標題字級至少為內文的 2.5 倍以拉開層次。
- 中英混排規則（CJK–Latin Mixed Typesetting）：處理中英混排：字體堆疊把英文字體放在中文字體之前，讓英文與數字優先使用英文字體；中文與英文、數字之間保留約四分之一個字寬的間隙；中文句子一律使用全形標點；中文內文行高設為 1.7 到 1.8，每行約 28 到 36 個中文字。
### 色彩
- 黑白灰加一個強調色（Monochrome + One Accent）：色彩採中性色加單一強調色：背景、文字、邊框只用黑、白與 4 到 5 階灰；另選一個強調色，只用在主要按鈕、連結、選中狀態與重點數字，面積不超過畫面的 10%。不得出現第二種彩色，成功與錯誤狀態除外。
- 深淺色可切換（Light & Dark Mode Toggle）：同時提供淺色與深色模式：所有顏色以語意化的自訂屬性定義（例如背景、表面、主要文字、次要文字、邊框、強調），兩種模式各給一組值。預設跟隨系統設定（prefers-color-scheme），並提供一個切換按鈕，選擇結果儲存在瀏覽器本機，下次造訪沿用。深色模式的背景用深灰而非純黑。
### 間距與形狀
- 直角（Sharp Corners）：全站所有元件的圓角一律為 0：按鈕、卡片、輸入框、圖片、標籤、彈出視窗都是直角。唯一的例外是頭像與狀態圓點可以是正圓。
- 細線分隔（Hairline Borders）：層次只靠邊框表達：卡片、輸入框與區塊分界使用 1px 實線，顏色為比背景略深的中性色；全站不使用任何陰影。浮層（下拉選單、彈出視窗）以稍深的邊框加上不同的底色與背景區分。
- 緊湊密集（Compact Density）：採緊湊的間距：所有間距取自 4px 的倍數階層（4、8、12、16、24）；表格列高 32px，按鈕高度 28px 到 32px，區塊間距不超過 24px。可點擊目標在觸控裝置上仍須至少 44px 高。
### 圖像與媒體
- 線條圖示（Line Icons）：圖示統一使用線條風格的內嵌 SVG：線寬 1.5px、端點與轉角為圓頭、畫在 24px 的格子上，顏色繼承文字顏色（currentColor）。整站只用同一套圖示，不混用填色圖示，也不得以表情符號代替圖示。純裝飾的圖示對輔助科技隱藏，單獨作為按鈕的圖示要有文字標籤。

## 動態與互動
- 不使用動態（No Motion）：全站不使用任何進場動畫、捲動動畫與自動播放的動態。唯一允許的變化是互動元素在懸停、聚焦、按下時的顏色或底線改變，過渡時間不超過 120 毫秒。

## 技術與交付
- React 專案（React + Vite Project）：成品是以 Vite 建立的 React 專案，使用 TypeScript：每個頁面區塊是一個獨立元件，放在 src/components。附上 package.json 與 README，說明安裝、啟動、建置三個指令與所需的 Node 版本。除 React 本身外，每多引入一個套件都要在 README 說明原因。
- Tailwind CSS（Tailwind CSS）：樣式使用 Tailwind CSS 的功能類別撰寫：設計變數集中定義在主題設定中（第 4 版以 CSS 的 @theme 區塊定義），元件裡只使用主題內的值，不用方括號任意值寫死數字。重複三次以上的類別組合要抽成元件。單檔交付沒有建置步驟，改用官方的瀏覽器版腳本，僅適合原型。
- 本機儲存（Local Storage Persistence）：使用者的設定與輸入內容儲存在瀏覽器的 localStorage：每次變更後 300 毫秒內寫入，載入頁面時還原。讀寫都要包在錯誤處理中且只在瀏覽器端執行，儲存空間不可用時網站仍能正常運作。儲存的資料帶版本號，並提供一個「清除資料」的操作。
- 交付方式：若你能在工作目錄建立檔案，請直接建立，完成後列出檔案清單與開啟方式；若不能，請逐一以程式碼區塊輸出每個檔案的完整內容，並在每個區塊的前一行標明檔案路徑。不得省略任何部分，也不得以「其餘相同」帶過。
### 品質要求
- 行動優先響應式（Mobile-First Responsive）：以行動優先的方式撰寫樣式：基礎樣式針對 375px 寬的螢幕，再以最小寬度的媒體查詢在 768px 與 1200px 逐步加寬版面。所有寬度下頁面整體都不得出現水平捲軸（容器內刻意的橫向捲動除外）；觸控裝置上的可點擊目標至少 44px 見方；圖片與影片不超出容器。
- 基本無障礙（Accessibility Basics (WCAG AA)）：達到 WCAG 2.2 AA 的基本要求：內文與背景對比至少 4.5:1，大字與介面元件至少 3:1；所有功能可只用鍵盤操作，聚焦時有清楚可見的外框；有意義的圖片有替代文字，裝飾圖片的替代文字留空；表單欄位都有關聯的標籤；不只靠顏色傳達資訊。
- 語意化 HTML（Semantic HTML）：使用語意化標籤建立結構：頁面有 header、main、footer 各一個地標，主導覽用 nav（多個 nav 要以 aria-label 區分）；每個區塊用 section 並有自己的標題；標題層級從 h1 開始依序遞降且不跳級，整頁只有一個 h1；可點擊的操作用 button，前往其他位置用 a；清單內容用 ul 或 ol。
- 搜尋與分享標籤（SEO & Social Meta Tags）：在 head 中加入完整的中繼資料：不超過 30 個中文字的 title、不超過 80 個中文字的 description、標準網址（canonical），以及 Open Graph 的標題、說明、圖片（1200×630）與類型，html 標籤設定 lang 屬性。每個頁面的 title 與 description 都不相同。

## 內容與文案
- 介面與文案語言：繁體中文（台灣用語）
- 語氣：平實直接（Plain & Direct）——文案平實直接：標題用一句話說出產品為使用者做到什麼，包含具體的對象或數字；每段不超過兩句、每句不超過 25 字，能省略主詞就省略；用動詞開頭的短句描述功能。不使用「革命性」「賦能」「一站式」「打造」這類空泛詞彙，不用驚嘆號，不用問句當標題。
- 依本規格的定位寫出具體、可直接上線的文案；不得使用 Lorem ipsum 或「標題文字」這類佔位字。素材沒提供的產品細節（功能、價格、日期）可自行合理設定並在「我的假設」中註明；客戶名稱、見證與成果數字若沒有提供，一律明確標示為「示意」。

## 禁止事項
- 禁用藍紫漸層（No Purple-Blue Gradients）：不得使用藍色到紫色的漸層，也不得使用漸層文字、背景光暈球與霓虹發光效果。背景使用純色；需要層次時改用明度不同的同色系色塊或留白。
- 禁用表情符號當圖示（No Emoji as Icons）：不得以表情符號作為圖示、項目符號或標題裝飾。需要圖示的地方使用風格一致的內嵌 SVG；沒有合適圖示時寧可不放。
- 禁用空泛標語（No Filler Copy）：文案不得使用放在任何產品都成立的空泛句子，例如「釋放潛能」「重新定義」「無縫整合」「賦能團隊」「次世代」。每個標題都要包含這個產品特有的對象、動作或數字；把產品名稱換成別的產品後句子仍然成立，就必須重寫。
