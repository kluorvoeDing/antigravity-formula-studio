# 任務
請製作一個完整的網站。
本文件是完整規格。請一次完成全部內容，不要只給大綱、片段或示意。
規格沒寫到的地方，不要停下來發問；請自行做出合理的決定，並在交付時以「我的假設」為標題逐條列出。
各項要求若互相牴觸，排在前面的優先：個人風格、禁止事項、視覺風格、色彩與字體與形狀、整體版型、個別區塊與元件。取捨的結果請一併列入「我的假設」。

## 定位與受眾
- 網站類型：SaaS 產品行銷頁（SaaS Landing Page）——這是一個軟體產品的行銷單頁，唯一目的是讓第一次來的訪客理解產品並完成註冊或試用。整頁只有一個主要行動，所有按鈕都導向它；內容順序為：價值主張、可信度、功能、價格、疑慮排除、再次號召。

## 頁面結構
### 整體版型
- 單欄置中（Single-Column Layout）：採單欄置中版型：各區塊由上到下依序堆疊、水平置中，不使用側欄；以文字為主的區塊，文字欄寬不超過 720px。區塊之間以 96px 的垂直間距分開。區塊內部需要並排的項目可以分欄，寬度小於 768px 時一律回到單欄。
### 區塊（由上到下，依此順序）
1. 固定頂部導覽列（Sticky Navbar）：頁面頂端放一條固定導覽列：左側是標誌，中間是 3 到 5 個錨點連結，右側是一個主要按鈕。捲動時導覽列固定在視窗頂端，離開頁首後加上不透明底色與一條細分隔線。寬度小於 768px 時把連結收進可開合的選單。
2. 左右分割主視覺（Split Hero）：首屏採左右兩欄：左欄放主標題（不超過 14 個字）、兩行以內的說明、一個主要按鈕與一個次要文字連結；右欄放產品畫面或情境圖，高度與左欄對齊。寬度小於 768px 時改為上下堆疊，文字在上。
3. 客戶標誌列（Logo Cloud）：放一列 5 到 6 個客戶標誌，統一為單色並降低對比，高度一致、間距相等；上方加一行不超過 16 個字的小標說明這些是誰。標誌不需要連結。寬度不足時改為兩列，不要橫向捲動。
4. 功能卡片網格（Feature Grid）：以區塊標題加一行說明開頭，下方排 3 或 6 張等寬卡片（桌面 3 欄、平板 2 欄、手機 1 欄）。每張卡片包含一個線條圖示、不超過 8 個字的功能名稱與兩行以內的說明；所有卡片高度一致，文字靠左對齊。
5. 方案定價表（Pricing Table）：並排 3 個方案卡，每張包含方案名稱、一句適用對象、價格與計費週期、5 到 7 條功能清單、一個按鈕。把中間的方案標示為推薦：加上標籤並用強調色的邊框或底色與其他兩張區分。上方提供月繳與年繳的切換，切換時價格即時更新。
6. 常見問題摺疊清單（FAQ Accordion）：列出 6 到 8 個常見問題，以摺疊清單呈現：每列顯示問題與一個展開指示圖示，點擊後在下方展開答案並旋轉圖示，再點一次收合。預設展開第一題。必須能用鍵盤的 Tab 與 Enter 操作，並為每列設定正確的展開狀態屬性（aria-expanded）。
7. 行動呼籲橫幅（CTA Band）：在頁尾之前放一個滿版橫幅，底色與前後區塊明顯不同。內容置中：一句不超過 16 個字的號召標題、一行說明、一個主要按鈕，可加一個次要文字連結。按鈕文字寫出具體動作（例如「開始免費試用」），不要寫「了解更多」。
8. 多欄頁尾（Multi-Column Footer）：頁尾分為 4 欄：第一欄放標誌與一句品牌描述，其餘 3 欄各有一個小標題與 4 到 5 個連結。最底部用一條細線隔開，左側放版權聲明，右側放隱私權政策與服務條款連結。寬度小於 768px 時改為 2 欄。

## 視覺系統
### 色彩
- 黑白灰加一個強調色（Monochrome + One Accent）：色彩採中性色加單一強調色：背景、文字、邊框只用黑、白與 4 到 5 階灰；另選一個強調色，只用在主要按鈕、連結、選中狀態與重點數字，面積不超過畫面的 10%。不得出現第二種彩色，成功與錯誤狀態除外。
- 只做淺色模式（Light Mode Only）：只提供淺色模式：明確宣告色彩配置為淺色（color-scheme: light），背景使用白色或極淺的中性色，文字使用接近黑色的深色。不實作深色模式，也不要跟隨系統的深色設定而改變外觀。
### 間距與形狀
- 分級圓角（Radius Scale）：圓角採三級階層並以自訂屬性定義：小型元件（按鈕、輸入框、標籤）6px，卡片 12px，大型容器與彈出視窗 20px。巢狀時內層圓角必須小於外層，差值等於兩者之間的內距。不得所有元件共用同一個圓角值。
- 細線分隔（Hairline Borders）：層次只靠邊框表達：卡片、輸入框與區塊分界使用 1px 實線，顏色為比背景略深的中性色；全站不使用任何陰影。浮層（下拉選單、彈出視窗）以稍深的邊框加上不同的底色與背景區分。
### 圖像與媒體
- 產品截圖（Product Screenshots）：以產品介面畫面作為主要圖像：畫面裝在只有三個圓點與細邊框的簡化視窗外框中。沒有真實截圖時，用 HTML 與 CSS 畫出一個內容具體、資料合理的介面示意，不要用模糊色塊或抽象圖形代替。截圖中的文字在桌面寬度下必須清晰可讀。
- 線條圖示（Line Icons）：圖示統一使用線條風格的內嵌 SVG：線寬 1.5px、端點與轉角為圓頭、畫在 24px 的格子上，顏色繼承文字顏色（currentColor）。整站只用同一套圖示，不混用填色圖示，也不得以表情符號代替圖示。純裝飾的圖示對輔助科技隱藏，單獨作為按鈕的圖示要有文字標籤。

## 動態與互動
- 克制的動態（Subtle Motion）：動態以回應操作為主：回應點擊與懸停的過渡時間在 150 到 250 毫秒之間，位移不超過 8px，緩動使用減速曲線（ease-out）。只有展開、收合、切換、出現與消失才有動畫；頁面載入時最多一段進場，之後不再有自動播放的動態。訪客設定減少動態（prefers-reduced-motion）時改為立即切換。
- 捲動顯現（Scroll Reveal）：區塊進入視窗時由下往上位移 16px 並淡入，時長 500 毫秒；同一組的項目依序延遲 60 毫秒。每個元素只播放一次，往回捲不重播。只套用在區塊標題與卡片群組，內文段落不套用。訪客設定減少動態時直接顯示。

## 技術與交付
- 單一 HTML 檔（Single HTML File）：成品是單一 HTML 檔：所有 CSS 寫在 head 的 style 標籤內，所有 JavaScript 寫在 body 結尾的 script 標籤內，不使用任何建置工具或框架。不得依賴外部檔案；字體可從公開的字體服務載入，但必須指定系統字體作為後備。檔案在沒有伺服器的情況下直接開啟即可完整運作。
- 原生 CSS 與自訂屬性（Plain CSS with Custom Properties）：樣式只使用原生 CSS：在根層級以自訂屬性定義設計變數（顏色、字級、間距、圓角、陰影），其餘樣式一律引用變數而不寫死數值。使用現代版面語法（Grid、Flexbox、clamp()、邏輯屬性），類別名稱以元件為單位命名。不使用任何 CSS 框架或前置處理器。
- 交付方式：若你能在工作目錄建立檔案，請直接建立，完成後列出檔案清單與開啟方式；若不能，請逐一以程式碼區塊輸出每個檔案的完整內容，並在每個區塊的前一行標明檔案路徑。不得省略任何部分，也不得以「其餘相同」帶過。
### 品質要求
- 行動優先響應式（Mobile-First Responsive）：以行動優先的方式撰寫樣式：基礎樣式針對 375px 寬的螢幕，再以最小寬度的媒體查詢在 768px 與 1200px 逐步加寬版面。所有寬度下都不得出現水平捲軸；可點擊目標至少 44px 見方；圖片與影片不超出容器。
- 基本無障礙（Accessibility Basics (WCAG AA)）：達到 WCAG 2.2 AA 的基本要求：內文與背景對比至少 4.5:1，大字與介面元件至少 3:1；所有功能可只用鍵盤操作，聚焦時有清楚可見的外框；有意義的圖片有替代文字，裝飾圖片的替代文字留空；表單欄位都有關聯的標籤；不只靠顏色傳達資訊。

## 內容與文案
- 介面與文案語言：繁體中文（台灣用語）
- 語氣：平實直接（Plain & Direct）——文案平實直接：標題用一句話說出產品為使用者做到什麼，包含具體的對象或數字；每段不超過兩句；用動詞開頭的短句描述功能。不使用「革命性」「賦能」「一站式」「打造」這類空泛詞彙，不用驚嘆號，不用問句當標題。
- 依本規格的定位寫出具體、可直接上線的文案；不得使用 Lorem ipsum 或「標題文字」這類佔位字。素材沒提供的事實（數字、客戶名稱、價格）請用合理的虛構內容，並在「我的假設」中註明。

## 禁止事項
- 禁用藍紫漸層（No Purple-Blue Gradients）：不得使用藍色到紫色的漸層，也不得使用漸層文字、背景光暈球與霓虹發光效果。背景使用純色；需要層次時改用明度不同的同色系色塊或留白。
- 禁用表情符號當圖示（No Emoji as Icons）：不得以表情符號作為圖示、項目符號或標題裝飾。需要圖示的地方使用風格一致的內嵌 SVG；沒有合適圖示時寧可不放。
- 禁用空泛標語（No Filler Copy）：文案不得使用放在任何產品都成立的空泛句子，例如「釋放潛能」「重新定義」「無縫整合」「賦能團隊」「次世代」。每個標題都要包含這個產品特有的對象、動作或數字；把產品名稱換成別的產品後句子仍然成立，就必須重寫。
