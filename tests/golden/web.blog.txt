# 任務
請製作一個完整的網站。
本文件是完整規格。請一次完成全部內容，不要只給大綱、片段或示意。
規格沒寫到的地方，不要停下來發問；請自行做出合理的決定，並在交付時以「我的假設」為標題逐條列出。
各項要求若互相牴觸，排在前面的優先：個人風格、禁止事項、網站類型、視覺風格、色彩與字體與形狀、整體版型、個別區塊與元件。取捨的結果請一併列入「我的假設」。

## 定位與受眾
- 網站類型：部落格（Blog）——這是一個以文章為主的部落格，目的是讓讀者讀完一篇後繼續讀下一篇或訂閱。首頁依發布時間由新到舊列出文章，每篇顯示標題、日期、預估閱讀時間與一句摘要；文章頁以閱讀為優先，文末提供相關文章與訂閱入口，導覽只保留分類、關於與搜尋。

## 頁面結構
### 整體版型
- 單欄置中（Single-Column Layout）：採單欄置中版型：各區塊由上到下依序堆疊、水平置中，不使用側欄，區塊之間保留一致的垂直間距。只有連續的長文段落限制行寬在 720px 以內；卡片列、圖片與表格等區塊不受此限，可以比段落寬並在區塊內並排分欄。寬度小於 768px 時一律回到單欄。
### 區塊（由上到下，依此順序）
1. 固定頂部導覽列（Sticky Navbar）：頁面頂端放一條固定導覽列：左側是標誌，中間是 3 到 5 個錨點連結，右側是一個主要按鈕。捲動時導覽列固定在視窗頂端，離開頁首後改為不透明背景，與下方內容明確區隔，避免文字透出重疊。寬度小於 768px 時把連結收進可開合的選單。
2. 純文字大標主視覺（Typographic Hero）：首屏只放文字：主標題不超過 12 個字、最多三行，字級約為視窗寬度的 8% 到 10%，靠左對齊並撐滿內容區寬度；下方一行不超過 30 字的說明與一個按鈕或文字連結。不放任何圖片或插圖。寬度小於 640px 時字級改為視窗寬度的 12% 左右，並避免最後一行只剩一個字。
3. 文章列表（Blog Post List）：區塊標題右側放「查看全部文章」連結，下方排 3 張最新文章卡（桌面 3 欄、平板 2 欄、手機 1 欄），每張包含 16:9 封面圖、分類標籤、最多兩行的標題、最多三行的摘要、發布日期與預估閱讀時間，整張卡片可點擊；超出行數時以刪節號截斷。
4. 電子報訂閱（Newsletter Signup）：放一個置中的訂閱區塊：一句不超過 20 字的標題寫出訂閱內容與頻率（例如「每週一封設計精選」），一列電子郵件輸入框與訂閱按鈕，下方一行小字註明可隨時取消。輸入框要有可見標籤或無障礙名稱；送出後在原位顯示成功或錯誤訊息。寬度小於 640px 時輸入框與按鈕上下堆疊。
5. 極簡頁尾（Minimal Footer）：頁尾只用一列：左側放標誌或品牌名稱與版權年份，右側放 2 到 4 個文字連結（例如隱私權政策、聯絡我們）與最多 4 個社群圖示，與上方內容明確隔開，上下留白保持緊湊。社群圖示要有無障礙名稱。寬度小於 640px 時改為置中的兩行，連結在上、版權在下。

## 視覺系統
### 視覺風格
- 編輯雜誌風（Editorial Design）：採編輯雜誌風格：主標題用高對比襯線字，字級至少為內文 3 倍；內文 17 到 19px、行高 1.7；區塊以 1px 細線與欄間距分隔；文章首段首字放大跨 3 行；以米白底配近黑字，只留一個重點色給標籤與連結；不使用圓角與陰影。
### 字體排印
- 全襯線（All-Serif System）：標題與內文都使用襯線體：中文用明體（例如 Noto Serif TC），英文用適合長文閱讀的 serif（例如 Source Serif 或 Lora）。標題字重 600 到 700、內文 400，內文字級不小於 17px，避免明體細橫線在螢幕上變糊；層次只靠字級與字重，不引入無襯線字。
- 中英混排規則（CJK–Latin Mixed Typesetting）：處理中英混排：字體堆疊把英文字體放在中文字體之前，讓英文與數字優先使用英文字體；中文與英文、數字之間保留約四分之一個字寬的間隙；中文句子一律使用全形標點；中文內文行高設為 1.7 到 1.8，每行約 28 到 36 個中文字。
- 理想行長與行高（Line Length & Leading）：長篇內文的文字區塊設定最大寬度：中文每行 28 到 36 個字，英文每行 60 到 75 個字元；中文內文行高 1.7 到 1.8，英文 1.5 到 1.6，標題行高 1.2 到 1.3。寬度小於 480px 時文字區塊佔滿可用寬度，左右至少保留 16px 留白。
### 色彩
- 帶色調的中性色（Tinted Neutrals）：所有中性色（背景、表面、邊框、次要文字、主要文字）都從同一個色相調出：以品牌主色（未指定則自選）的色相為基準，OKLCH 色度約 0.005 到 0.02，只改變明度，做出 6 到 8 階，不混用純灰。強調色另外處理，不受此限。文字對比達 4.5:1。
- 深淺色可切換（Light & Dark Mode Toggle）：同時提供淺色與深色模式：所有顏色以語意化的自訂屬性定義（例如背景、表面、主要文字、次要文字、邊框、強調），兩種模式各給一組值。預設跟隨系統設定（prefers-color-scheme），並提供一個切換按鈕，選擇結果儲存在瀏覽器本機，下次造訪沿用。深色模式的背景用深灰而非純黑。
### 間距與形狀
- 直角（Sharp Corners）：全站所有元件的圓角一律為 0：按鈕、卡片、輸入框、圖片、標籤、彈出視窗都是直角。唯一的例外是頭像與狀態圓點可以是正圓。
- 細線分隔（Hairline Borders）：層次只靠邊框表達：卡片、輸入框與區塊分界使用 1px 實線，顏色為比背景略深的中性色；全站不使用任何陰影。浮層（下拉選單、彈出視窗）以稍深的邊框加上不同的底色與背景區分。
- 寬鬆留白（Generous Whitespace）：採寬鬆的間距：所有間距取自 8px 的倍數階層（8、16、24、40、64、96、144）；區塊之間的垂直間距在桌面為 144px、手機為 80px；標題與內文之間 24px；一個視窗高度內只放一個主要訊息。
### 圖像與媒體
- 實景照片（Photography）：圖像以實景照片為主：所有照片使用同一種色調與裁切比例（主視覺 16:9、卡片 4:3），避免擺拍感強的圖庫照。每張圖片都要設定寬高屬性與描述性的替代文字，首屏以外的圖片延遲載入。沒有實際照片時，以相同比例的中性色塊佔位並在其上標示應放的內容。

## 動態與互動
- 克制的動態（Subtle Motion）：動態以回應操作為主：點擊與懸停的過渡預設 150 到 250 毫秒、位移不超過 8px、緩動用減速曲線（ease-out），展開、收合、切換、出現與消失才加動畫，預設不加自動播放的裝飾動態。已選效果另有時長、曲線或減少動態規定時，以該效果為準；訪客設定減少動態（prefers-reduced-motion）時改為立即切換。
- 閱讀進度條（Scroll Progress Indicator）：只在文章內頁的視窗頂端加一條 3px 高的進度條，寬度依文章本體（不含頁尾與留言）的捲動比例由 0% 增加到 100%，即時跟隨捲動、不加任何過渡。進度條設為 aria-hidden、不攔截點擊，也不遮住導覽列。訪客設定減少動態時照常顯示，因為它只反映捲動位置、不是動畫。

## 技術與交付
- Astro 專案（Astro Site）：成品是 Astro 專案：頁面放在 src/pages，每個 .astro 檔對應一個網址，共用外框放在 src/layouts，元件放在 src/components，靜態素材放在 public。預設輸出靜態 HTML 且不送出 JavaScript，只有需要互動的元件才以 client 指令載入。附上 README 說明安裝、開發、建置指令，每多引入一個套件或整合都要說明原因。
- 原生 CSS 與自訂屬性（Plain CSS with Custom Properties）：樣式只使用原生 CSS：在根層級以自訂屬性定義設計變數（顏色、字級、間距、圓角、陰影），其餘樣式一律引用變數而不寫死數值。使用現代版面語法（Grid、Flexbox、clamp()、邏輯屬性），類別名稱以元件為單位命名。不使用任何 CSS 框架或前置處理器。
- Markdown 內容來源（Markdown Content）：內容以 Markdown 檔存放在 專案的內容資料夾（例如 Astro 的 src/content），每篇開頭用 frontmatter 記錄標題、日期、摘要與標籤，建置時檢查欄位是否齊全。列表頁依日期新到舊自動產生，文章網址由檔名決定。附一篇示範文章，並在 README 說明新增文章的步驟。
- 交付方式：若你能在工作目錄建立檔案，請直接建立，完成後列出檔案清單與開啟方式；若不能，請逐一以程式碼區塊輸出每個檔案的完整內容，並在每個區塊的前一行標明檔案路徑。不得省略任何部分，也不得以「其餘相同」帶過。
### 品質要求
- 行動優先響應式（Mobile-First Responsive）：以行動優先的方式撰寫樣式：基礎樣式針對 375px 寬的螢幕，再以最小寬度的媒體查詢在 768px 與 1200px 逐步加寬版面。所有寬度下頁面整體都不得出現水平捲軸（容器內刻意的橫向捲動除外）；觸控裝置上的可點擊目標至少 44px 見方；圖片與影片不超出容器。
- 基本無障礙（Accessibility Basics (WCAG AA)）：達到 WCAG 2.2 AA 的基本要求：內文與背景對比至少 4.5:1，大字與介面元件至少 3:1；所有功能可只用鍵盤操作，聚焦時有清楚可見的外框；有意義的圖片有替代文字，裝飾圖片的替代文字留空；表單欄位都有關聯的標籤；不只靠顏色傳達資訊。
- 語意化 HTML（Semantic HTML）：使用語意化標籤建立結構：頁面有 header、main、footer 各一個地標，主導覽用 nav（多個 nav 要以 aria-label 區分）；每個區塊用 section 並有自己的標題；標題層級從 h1 開始依序遞降且不跳級，整頁只有一個 h1；可點擊的操作用 button，前往其他位置用 a；清單內容用 ul 或 ol。
- 搜尋與分享標籤（SEO & Social Meta Tags）：在 head 中加入完整的中繼資料：不超過 30 個中文字的 title、不超過 80 個中文字的 description、標準網址（canonical），以及 Open Graph 的標題、說明、圖片（1200×630）與類型，html 標籤設定 lang 屬性。每個頁面的 title 與 description 都不相同。
- 字體載入策略（Font Loading Strategy）：網頁字體使用 WOFF2 格式並設定 font-display: swap，下載期間先以系統字顯示；只預先載入（preload）首屏用到的字體，最多 2 個檔案。中文字體依實際用字做子集化，或以 unicode-range 分割成多個小檔按需下載。
- 結構化資料（Structured Data (JSON-LD)）：以 JSON-LD 格式加入符合 Schema.org 的結構化資料，依頁面性質選用 Organization、LocalBusiness、Product、Article、Event 或 BreadcrumbList 等類型；放在 type 為 application/ld+json 的 script 標籤中，每個標記值都必須與頁面上看得到的內容一致，該類型的必填屬性不可缺漏。

## 內容與文案
- 介面與文案語言：繁體中文（台灣用語）
- 語氣：敘事感（Storytelling）——文案帶敘事感：首屏以一個具體人物在具體時間遇到的困境開場；以第三人稱，依「困境、轉折、改變後的日常」三段推進，每段 2–4 句、每句不超過 25 字，細節寫出時間、次數與動作。人物用職稱代稱，不編造看似真實的姓名與公司；不用「想像一下」「從前從前」這類套語，功能說明放在故事後另列清單。
- 依本規格的定位寫出具體、可直接上線的文案；不得使用 Lorem ipsum 或「標題文字」這類佔位字。素材沒提供的產品細節（功能、價格、日期）可自行合理設定並在「我的假設」中註明；客戶名稱、見證與成果數字若沒有提供，一律明確標示為「示意」。

## 禁止事項
- 禁用藍紫漸層（No Purple-Blue Gradients）：不得使用藍色到紫色的漸層，也不得使用漸層文字、背景光暈球與霓虹發光效果。背景使用純色；需要層次時改用明度不同的同色系色塊或留白。
- 禁用表情符號當圖示（No Emoji as Icons）：不得以表情符號作為圖示、項目符號或標題裝飾。需要圖示的地方使用風格一致的內嵌 SVG；沒有合適圖示時寧可不放。
- 禁用空泛標語（No Filler Copy）：文案不得使用放在任何產品都成立的空泛句子，例如「釋放潛能」「重新定義」「無縫整合」「賦能團隊」「次世代」。每個標題都要包含這個產品特有的對象、動作或數字；把產品名稱換成別的產品後句子仍然成立，就必須重寫。
- 禁止處處加小標（No Eyebrow Labels Everywhere）：不得在區塊標題上方加固定格式的小字標籤。標題本身要直接說明內容；全頁最多保留一處小標籤，且內容必須是分類、日期或編號這類真實資訊，不得只是重述標題。
